## Services Added

### getFarmerOrders(pool, farmerId, options)

**Purpose**: Fetch filtered farmer orders with pagination support

**Parameters**:
- `pool`: Database connection pool
- `farmerId`: Farmer user ID
- `options`: Query options (status, dateFrom, dateTo, sort, page, limit, includeCount)

**Returns**: `{ orders, total, page, limit }`

**SQL Logic**:
- Filters by farmer's products: `(p.farmer_id = $1 OR p.farmer_id IS NULL)`
- Excludes disabled orders: `COALESCE(o.is_disabled, false) = false`
- Supports status filtering
- Supports date range filtering
- Supports sorting (reuses existing `getSortSql()` function)
- Supports pagination

**Reused Components**:
- `getSortSql()` function for sorting logic
- Same pagination pattern as `getAdminOrders()`

### computeFarmerOrderSummary(rows)

**Purpose**: Calculate farmer-specific order summary metrics

**Parameters**:
- `rows`: Array of order rows

**Returns**: `{ totalOrders, totalRevenue, deliveredOrders, pendingOrders, cancelledOrders, totalItemsSold }`

**Business Logic**:
- Total revenue: Sum of delivered orders only
- Total items sold: Sum of quantities from delivered orders
- Status counts: Based on effective status (disabled orders treated as 'disabled')

**Reused Components**:
- Same status handling logic as `computeOrderSummary()`
- Added totalItemsSold for farmer-specific requirement
