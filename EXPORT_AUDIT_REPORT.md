# AgriCatch Export Feature Audit

**Date:** 2026-07-09  
**Scope:** Admin and Farmer modules, backend APIs, frontend UI triggers, data consistency, export quality, code reuse, and missing opportunities.  
**Methodology:** Static code review + runtime verification via Chrome DevTools (live backend at `http://localhost:3000`).

---

## 1. Executive Summary

### Existing Export Capabilities

| Module | Role | Export Button | Endpoint(s) | Format | Verified Live |
|--------|------|--------------|-------------|--------|---------------|
| Dashboard | Admin | `export-dashboard-btn` in `overview` section | `GET /api/admin/dashboard/export.xlsx` | Excel | 200 OK |
| Orders | Admin | `order-export-btn` in `orders` section | `GET /api/admin/orders/export.xlsx` | Excel | 200 OK |
| Dashboard | Farmer | `export-dashboard-btn` in `overview` section (premium only) | `GET /api/farmers/me/metrics/export.xlsx` | Excel | 200 OK |
| Dashboard | Farmer | None (backend only) | `GET /api/farmers/me/metrics/export.csv` | CSV | 200 OK |

All four endpoints are functional and return correctly formatted Excel/CSV files.

### High-Level Findings

- **Existing exports are well-implemented** for Admin Dashboard and Farmer Dashboard, with professional ExcelJS formatting, branding, and metadata.
- **Admin Orders export** is an additional, filter-aware Excel export that respects UI search, status, date range, and sort.
- **Farmer CSV export** exists but has no UI trigger; only reachable by direct API call.
- **Major export gaps** exist in Admin Users, Products, Farmers, Customers, Categories, Support Tickets, Audit Logs, and Farmer Orders/Products/Reviews.
- **Code reuse is inconsistent**: Admin Orders export uses a shared `orderExportService.js`; Dashboard exports in `admin.js` and `farmers.js` duplicate inline styling/branding logic. `dashboardService.getFarmerExportData` is exported but unused.

### 2.3 Export Quality Assessment

#### Excel Exports

| Criterion | Admin Dashboard | Admin Orders | Farmer Dashboard |
|-----------|-----------------|--------------|------------------|
| Logo | Yes (`resendlogo.png`) | Yes (`resendlogo.png`) | Yes (`resendlogo.png`) |
| Title | Yes | Yes | Yes |
| Report metadata (period, generated at) | Yes | Yes | Yes |
| Generated by (name, email, role) | Yes | Yes | Yes |
| KPI/summary section | Yes | Yes | Yes |
| Filter description | No | Yes | No (range only) |
| Column widths | Yes | Yes | Yes |
| Currency formatting (₱) | Yes | Yes | Yes |
| Date/time formatting | Yes | Yes | Yes |
| Borders/alternating colors | Yes | Yes | Yes |
| Footer branding | Yes | Yes | Yes |
| Multiple sheets | No (single sheet) | No | No |

Overall Excel export quality is **good to excellent**.

#### CSV Export

- **Header:** Manual row headers; no BOM (UTF-8 is set in Content-Type).
- **Delimiter:** Comma.
- **Escaping:** Custom `csvEscape` handles commas, quotes, newlines.
- **Numeric/date handling:** Prefixes dates and amounts with a single quote (`'`) to force Excel to treat as text. This works in Excel but is a non-standard CSV convention.
- **Issue:** No UI trigger; no filter summary in file; no branding in CSV.
- **Issue:** No BOM means Excel may not auto-detect UTF-8, causing garbled non-ASCII characters for some users. **LOW** priority.

### 2.4 Data Consistency

#### Farmer Dashboard

- **Metrics API:** `GET /api/farmers/me/metrics?rangeDays=30` returned orders by status, top products, and recent orders.
- **Excel Export:** `GET /api/farmers/me/metrics/export.xlsx?rangeDays=all` returns all-time data, matching the dashboard structure.
- **CSV Export:** `GET /api/farmers/me/metrics/export.csv?rangeDays=all` returned all-time summary `Total Orders=176, Total Sold=24, Total Sales=3046.00`.
- **Consistency:** Export SQL and dashboard metrics SQL are aligned on `p.farmer_id = $1`, `status` filters, `COALESCE(o.is_disabled, false) = false`, and `o.created_at` range.
- **Concern:** Farmer dashboard metrics use `getFarmerDashboardMetrics` (dashboardService.js), while the export endpoints in `farmers.js` use inline SQL. The two are similar but not identical, creating a small risk of drift. `dashboardService.getFarmerExportData` exists but is not used. **MEDIUM** priority.

#### Admin Dashboard

- **Stats API:** `GET /api/admin/dashboard/stats?period=all` returned `sales: 244, revenue: 56123.90, customers: 30, farmers: 46`.
- **Excel Export:** `GET /api/admin/dashboard/export.xlsx?period=all` returned 200. The export uses the same `getAdminDashboardStats` service for KPIs, ensuring consistency with the dashboard.
- **Additional data** (trends, top products, top farmers) is fetched directly in the route and not shared with the dashboard API. This is acceptable for an export-only report, but could be centralized. **LOW** priority.

#### Admin Orders

- **Orders API:** `GET /api/admin/orders` uses `getAdminOrders` from `orderExportService.js` with pagination.
- **Export API:** `GET /api/admin/orders/export.xlsx` uses the same `getAdminOrders` with `limit=0` and `includeCount=false`.
- **Consistency:** Filter logic is identical; export matches the current UI filters. **HIGH** quality.

### 2.5 Code Reuse and Standardization

#### Positive Reuse

- **`orderExportService.js`** centralizes `getAdminOrders`, `computeOrderSummary`, and `buildAdminOrdersExcel` for the Admin Orders list and export. This is a good pattern.
- **`dashboardService.js`** provides shared `getPeriodFilter`/`getPrevPeriodFilter` used by dashboard stats and some export logic.
- **`admin.js`** and **`farmers.js`** use the same `ExcelJS` library and same logo path.

#### Negative Reuse / Duplication

- **Dashboard exports** (`admin.js` and `farmers.js`) contain large inline blocks of ExcelJS styling (colors, fonts, borders, column widths, footer, logo). These are not shared in a common helper.
- **Duplicate styling constants:** `agricatchGreen`/`lightGreen`/`darkGreen` are defined locally in both `admin.js` and `orderExportService.js`.
- **Unused function:** `dashboardService.getFarmerExportData` is exported but never imported; `farmers.js` duplicates its logic. **MEDIUM** priority.
- **No shared `exportBuilder` utility** for title, logo, metadata, footer, or table styling.

#### Recommendations for Code Reuse

1. Create `backend/services/exportService.js` or `backend/utils/excelExport.js` with:
   - `createBrandedWorkbook(title, options)`
   - `addLogo(ws)`
   - `addReportInfo(ws, { period, generatedAt, generatedBy, filters })`
   - `addTable(ws, headers, rows, startRow, options)`
   - `addFooter(ws)`
2. Refactor `admin.js`, `farmers.js`, and `orderExportService.js` to use this shared builder.
3. Remove or use `dashboardService.getFarmerExportData`.

## 4. Issues and Recommendations

### 4.1 Critical Issues

None found. All existing export endpoints are functional and do not expose unauthorized data.

### 4.2 High-Priority Issues

1. **Missing export for high-volume Admin lists** (Users, Products, Farmers, Product Approvals). Admins currently cannot export these lists, which is a common operational need.
   - **Recommendation:** Add `export.xlsx` endpoints using the shared `getAdminOrders`/`buildAdminOrdersExcel` pattern, and add UI `Export` buttons.

2. **Missing Farmer Orders export.** Farmers can view orders but cannot export them.
   - **Recommendation:** Add `GET /api/farmers/me/orders/export.xlsx` and `export.csv` with filters, and a UI button in the Orders section.

### 4.3 Medium-Priority Issues

1. **Farmer CSV export has no UI trigger.** The endpoint exists but is only reachable via direct API.
   - **Recommendation:** Add a "Download CSV" option in the farmer export modal or remove the endpoint.

2. **Admin Orders export references non-existent `order-price-filter` and `order-sort-filter` DOM elements.** The export reads `document.getElementById('order-price-filter')?.value` and `getCurrentOrderSort()` (which checks `order-sort-filter`), but neither element exists in `admin.html`.
   - **Recommendation:** Add the price filter dropdown and sort dropdown to the Orders filter bar, or remove the unused code paths.

3. **Duplicate Excel styling logic in `admin.js` and `farmers.js` routes.** Dashboard exports are large, inline, and hard to maintain.
   - **Recommendation:** Extract shared Excel builder utilities.

4. **`dashboardService.getFarmerExportData` is unused.** The function is exported but not imported; `farmers.js` duplicates the logic.
   - **Recommendation:** Either use `getFarmerExportData` in the CSV/Excel endpoints or remove it.

### 4.4 Low-Priority Issues

1. **CSV exports lack a UTF-8 BOM.** Some Excel versions may not auto-detect UTF-8, causing garbled non-ASCII characters.
   - **Recommendation:** Add `\uFEFF` BOM at the start of CSV responses.

2. **CSV export uses a leading single-quote trick for Excel.** This is non-standard and may cause issues in other spreadsheet tools.
   - **Recommendation:** Consider writing raw numeric/date values and documenting expected CSV consumers, or switch to a CSV library.

3. **No Excel export for `today` period in Farmer Dashboard?** The period modal supports `today` and the endpoint accepts `rangeDays=1` indirectly; this is fine but the UI modal uses `today` mapping.

## 7. Conclusion

AgriCatch has a solid foundation for exports in the **Admin Dashboard**, **Admin Orders**, and **Farmer Dashboard** modules. The Excel reports are well-formatted, branded, and include useful metadata. The main opportunities are:

1. **Expanding exports** to the high-traffic Admin Users, Products, Farmers, and Product Approvals sections, and Farmer Orders/Products.
2. **Standardizing** the Excel-building code into a shared utility to reduce duplication and maintenance risk.
3. **Fixing small UI/API inconsistencies** (Farmer CSV reachability, missing price/sort filters in Admin Orders).

No critical security or functional issues were found in the existing export endpoints. All endpoints enforce role-based access and premium-tier gating appropriately.
